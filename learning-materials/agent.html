Agent（智能体）

Agent · AI Agent · 智能体
领域：人工智能 / 大模型应用 目标读者：初学者 深度：入门到进阶 检索日期：2026-09-05

1个人解释

普通聊天机器人像一个问一句答一句的客服：你问，它答，答完就结束了。而 Agent 更像一个能自己想办法的助理——你交给她一个目标（比如"帮我把这次出差报销提交了"），她会自己列出步骤：识别发票照片、查出金额、判断是否符合公司标准、提交系统；发现金额超了上限，她会停下来问你怎么办，得到答复后继续，直到任务完成。

换句话说，Agent 和聊天机器人的本质区别不在于"聪明多少"，而在于谁在控制流程：聊天机器人按你的节奏被动应答，Agent 自己规划、自己行动、自己根据结果调整（类比：流水线工人 vs 能独立接活的助理；该类比仅在"自主安排工作节奏"这一点上成立，Agent 并没有人类助理那样的常识和责任能力）。

2核心机制

Anthropic 给出的工作定义是：Agent 是在完成任务时自己指挥自己的流程和工具使用的 AI 模型——即自己决定"怎么做到用户想要的结果"，而不是按固定脚本执行。它运行在一个自驱动的循环里：规划 → 行动 → 观察结果 → 调整 → 重复，直到任务完成或需要请示人类。

四大组成部分（Anthropic 框架）

  • 模型（Model）：Agent 的"大脑"，提供理解、推理和决策能力。
  • 约束框架（Harness）：模型运行的指令和安全护栏，例如"超过 100 美元的支出必须先请用户确认"。
  • 工具（Tools）：模型可以调用的外部服务——邮箱、日历、代码执行器等。没有工具，模型"看得懂发票却交不了单"。
  • 环境（Environment）：Agent 运行的场所及其可访问的文件、网站和系统，决定了它的数据边界和风险等级。

经典能力公式

Agent = LLM（大脑） + Memory（记忆） + Planning（规划） + Tool Use（工具调用）
—— 业界广泛引用的公式（源自 Lilian Weng 的经典总结）
  • 规划：把复杂任务拆成子步骤，常见模式有 ReAct（推理↔行动交替）、先规划后执行等；执行中可根据反馈动态重新规划。
  • 记忆：短期记忆即当前对话的上下文；长期记忆通常借助外部存储（如向量数据库）实现跨会话的记住。
  • 工具调用：模型不直接执行操作，而是输出结构化的调用请求（函数名 + JSON 参数），由运行时代码执行后把结果回传给模型。

关键循环：ReAct

Agent 最典型的工作方式是 Thought（思考）→ Action（行动）→ Observation（观察） 的循环：模型先推理"当前状态离目标还差什么"，选择一个工具执行，读回结果，再决定下一步——这也是它能够纠错的原因：如果某一步失败，观察结果会暴露问题，Agent 可以换一条路重试。

3应用场景

  • 编程 Agent：开发者描述一个需求（如"修复这个 bug，涉及多个文件"），Agent 自己读代码、定位问题、修改多个文件、跑测试验证。代码任务特别适合 Agent，因为测试结果提供了明确的成败反馈。
  • 客户支持：Agent 在对话中调用工具查询订单、读取知识库、办理退款——把"会聊天"和"能办事"结合，成功标准明确（用户问题是否解决）。
  • 办公事务自动化：如提交报销——Agent 逐张识别票据、提取金额与商家、归类提交，遇到超限等异常主动请示人类后继续。
  • 操作电脑（Computer Use）：Agent 像人一样看屏幕、点鼠标、敲键盘，操作没有 API 的传统软件界面完成任务。
典型失效情况：开放式任务中步骤数不可预测，自主性带来更高的成本和误差累积——一步走偏可能连环出错。因此 Anthropic 的建议是：先用沙箱环境和护栏充分测试，任务能用确定性的 Workflow 解决时，就不要用 Agent。

4边界辨析

对比A 是……B 是……
Agent vs Chatbot运行在自驱循环中，自己规划并调用工具，主动与环境交互一问一答的问答机，不规划、不用工具、被动响应
Agent vs Workflow控制流由 LLM 动态决定，适合步骤数不可预测的开放式任务控制流由预定义代码决定，LLM 只是流程中的一环，可预测、易调试
Agent vs RAG会"做事"：规划、执行操作、根据反馈调整只解决"找资料"：检索相关文档给模型参考，流程固定（检索→生成）

适用边界

该用 Agent：任务开放式、步骤数无法预知、需要根据中间结果临场决策。不该用 Agent：任务步骤固定可枚举（一条 Workflow 或一个写好的提示词就够）——为 Agent 而 Agent 只会带来更高延迟、更高成本和更多失败模式。

常见误解

  • 误解一：越"Agent 化"越先进。恰恰相反，行业共识（Anthropic《Building Effective Agents》）是"从最简单的方案开始，只有简单方案 demonstrably 不够时才增加复杂度"。多数任务只需要 Workflow 甚至单个好的提示词。
  • 误解二：Agent = 更聪明的大模型。Agent 是"模型 + 护栏 + 工具 + 环境"四层协作的系统工程：一个强模型配上糟糕的工具描述或过宽的权限，照样产出不可靠甚至危险的 Agent。
