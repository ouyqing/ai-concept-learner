Agent Memory（智能体记忆）

Agent Memory / Working Memory vs Long-term Memory
领域：AI Agent / 上下文工程 读者：进阶学习者 深度：入门到进阶 检索日期：2026-09-16

1个人解释

想象你在和一位只有 7 秒记忆的朋友聊天——他能回答你当前的句子，却不记得你三分钟前说过他叫什么名字、你喜欢什么。Agent Memory 就是给这位朋友装上一块外接硬盘，让他能记住"我是谁、我偏好什么、我以前解决过哪些问题"，并且能在需要时快速调取。

在工程上，Agent Memory 是让大模型突破上下文窗口限制、在多次会话中保持一致性的整套机制——既包括临时塞进提示词的短期记忆，也包括写入向量数据库或键值库的长期事实（类比成立的前提是承认"记住"≠"理解"，记忆只是把信息存储起来供检索）。

2核心机制

三种时间尺度

类型存什么怎么用
短期（Working）当前会话的对话历史直接拼进提示词；超长就截断或摘要
长期（Long-term）用户偏好、过往结论、个性化事实向量化后相似度检索，命中片段回填
情景/语义/程序性具体事件（情景）· 概念知识（语义）· 操作步骤（程序）按需分类检索

典型读写流程

写入：每轮对话结束 → 抽取"值得记的事实"（用户姓名、偏好、决定）→ 嵌入 → 写入向量库
读取：新一轮开始 → 用当前 query 做相似度检索 → 取出 top-k 条目 → 与对话历史拼成 prompt

3应用场景

  1. 个人助理跨会话记忆：记住用户是素食者、习惯每周二开会、不能吃花生
  2. 客户支持 Agent：记住上次通话的投诉编号、用户已尝试过的方案，避免重复
  3. 研究 Agent：积累每次实验结论、引用过的文献，避免下次重复查
  4. 代码助手：记住项目命名约定、用户偏好的库版本、过往踩坑记录
  5. 学习 Agent：记忆用户的薄弱知识点，按错题本式复习

4边界辨析

易混项核心区别
记忆 vs 上下文窗口窗口是"临时内存"（断电丢）；记忆是"外接硬盘"（持久存）
记忆 vs RAGRAG 是从文档库检索；记忆是从"关于用户/自身的事实库"检索
记忆 vs 微调微调改"模型参数"，记忆改"输入内容"；前者永久但昂贵，后者灵活
常见误解："记忆越多越好"——错。记忆会带来噪声与无关信息，反而干扰判断。工程要点是取舍：值得记什么、什么时候记、什么时候忘（过期清理）。
