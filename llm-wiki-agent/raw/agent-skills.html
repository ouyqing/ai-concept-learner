Agent Skills（智能体技能）

1个人解释

想象给你的"只有 7 秒记忆的朋友"配一本岗位操作手册：他不知道你们公司报销怎么走，你就把流程写进一本《财务部报销手册》，需要时他翻开照做。Skill 就是 Agent 的"岗位手册"——把"什么时候做、按什么步骤做、做错了怎么办"打包成一份可复用的能力单元。

Skill 填的是"一条提示词太零散、一个工具又太原子"之间的空档（类比在"按需查阅的工作手册"这一点上成立；Skill 不改变模型本身的能力）。

2核心机制

典型结构

一个 Skill 就是一个文件夹，核心是 SKILL.md：YAML 元数据（name + description）+ Markdown 工作流说明。可选附属：scripts/、assets/、references/。

三段式工作流

① 触发判断（LLM 看 description 决定调不调用）→ ② 加载内容（按需把 SKILL.md 全文或部分塞进 prompt）→ ③ 执行（按工作流跑脚本或对话）

3应用场景

  1. 领域工作流："分析销售数据"、"生成周报"、"排查线上告警"
  2. 角色化操作：财务报销、法务合同初稿、HR 入职流程
  3. 项目专属：某个研究项目的实验记录模板、文献综述模板
  4. 个人偏好：用你的写作风格改稿、用你的笔记结构整理材料

4边界辨析

易混项核心区别
Skill vs ToolTool 是单步原子操作（如"查天气"）；Skill 是多步工作流（如"查三天天气+给穿衣建议"）
Skill vs PromptPrompt 是本次对话指令；Skill 是持久化资产，任何会话都能调用
Skill vs Fine-tuneFine-tune 改模型参数；Skill 改输入内容，不动模型
常见误解："Skill 越多 Agent 越聪明"——错。Skill 是任务模板而非通用能力；过多 Skill 会让触发判断变难、上下文变长。要按"使用频率 + 复用价值"取舍。
