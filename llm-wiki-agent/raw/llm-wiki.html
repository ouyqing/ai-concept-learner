LLM Wiki Agent（知识库代理）

llm-wiki / Knowledge Base Agent
领域：AI Agent / 个人知识管理 读者：入门 深度：工具级 检索日期：2026-09-16

1个人解释

把 LLM Wiki 想成一位专管资料室的图书管理员：你丢给他一摞文档（论文、网页、笔记），他会把每份做摘要、抽出关键观点、按主题分类归档；以后你想查"什么是 RAG"，他翻目录、查条目、组织成一段带原文引用的答案——全部在 Markdown 文件里完成。

它是由 Claude Code 维护的本地知识库系统，分层：raw/（原始资料）→ wiki/（结构化页面）→ graph/（知识图谱）（类比成立的前提是承认"由 LLM 自动维护"意味着资料质量受模型能力约束）。

2核心机制

三层资料

① raw/ 不可变原始资料（PDF/MD/HTML）→ ② wiki/ 结构化页面（sources/entities/concepts/syntheses）→ ③ graph/ 知识图谱（节点 + 关系）

五个工作流

  • ingest：摄取新资料，写 sources 页面
  • query：检索+综合回答
  • health：结构健康检查（每会话跑，零 LLM 调用）
  • lint：内容质量审计（孤儿页、断链、矛盾）
  • graph：构建知识图谱（vis.js 可视化）

3应用场景

  1. 学术研究：把 50 篇 arXiv 论文入档，按方法/数据集/结果对比
  2. 个人读书笔记：导入 kindle clippings → 自动主题归类
  3. 团队 wiki：把会议记录、决策文档、需求文档统一索引
  4. 产品调研：批量分析竞品文档，抽共同关注点

4边界辨析

易混项核心区别
LLM Wiki vs NotionNotion 手动整理；LLM Wiki 自动摘要+链接+图谱
LLM Wiki vs RAGRAG 是检索增强生成；LLM Wiki 是带索引的持久知识库（包含 RAG）
LLM Wiki vs Vector DBVector DB 只存向量；LLM Wiki 存可读的 Markdown 页面
