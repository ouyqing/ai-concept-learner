Agent Memory System（记忆系统架构）

Memory Architecture / Pipeline · Memory System
领域：AI 工程 读者：进阶 深度：架构级 检索日期：2026-09-16

1个人解释

如果说"Agent Memory"是问"记得什么"，那么"Memory System"问的是"怎么记得更靠谱"——就像一家公司不会只让一个人保管账本，会有出纳、会计、审计三种角色。Memory System 就是给 Agent 设计一整套"账本制度"：谁写、怎么分类、什么时候翻旧账、什么时候核销。

工程上，Memory System 是把写入、存储、检索、遗忘四个环节做成可维护管线的设计（类比成立的前提是承认记忆系统有"运维成本"，不像简单缓存那样无脑用）。

2核心机制

四类记忆（按维度）

  • 事实型：用户的姓名、生日、偏好——键值对存
  • 事件型：用户上周订过哪家餐厅、踩过哪些坑——时间序列存
  • 语义型：领域知识（如"Linear Regression 用于回归"）——向量库存
  • 程序型：操作流程（如"先备份再部署"）——步骤模板存

管线五步

① 抽取（从对话/工具结果识别值得记的内容）→ ② 分类（事实/事件/语义/程序）→ ③ 写入（选合适存储：SQL/向量/队列）→ ④ 检索（query 来了就查）→ ⑤ 遗忘（过期、冲突、噪声清理）

3应用场景

  1. 长期陪伴型 AI：陪伴机器人需要分清事实型（用户生日）与事件型（今天聊了什么）
  2. 专业领域 Agent：医生 Agent 把病历、文献、操作流程分类入不同库
  3. 多 Agent 协作：主 Agent 与子 Agent 共享一个 memory bus，跨 Agent 经验沉淀
  4. 个人知识库：LLM Wiki / Obsidian 风格——把网页/笔记/对话都按四类入档

4边界辨析

易混淆：Memory System ≠ Database。前者关心"什么时候忘、什么时候记"，后者关心"怎么高效存取"。没有取舍机制的记忆库会越长越杂，最终像没整理过的邮箱一样难用。

常见误解：以为只要把所有对话塞进向量库就完事了——错。对话里有大量噪声（"嗯""那个"），不抽"事实"会让检索命中率骤降。
