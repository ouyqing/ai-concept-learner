Agent（智能体）

AI Agent / Autonomous Agent
领域：人工智能 / 大模型应用 目标读者：初学者 深度：入门 检索日期：2026-09-16

1个人解释

把大模型想成一位博览群书却从没下过厨房的食神：他知道"少许盐""中火翻炒"是什么意思，但没人指挥他就会一直站着。Agent 就是给这位食神配的厨房工作流：明确的目标、一步步的判断、能伸手够到的工具（冰箱、锅铲、计时器），以及做完之后回头复盘的习惯。

在工程上，Agent 是把"语言能力"和"做事能力"缝合起来的一类系统——它由"思考引擎（LLM）+ 外部工具 + 长期记忆 + 规划能力"组成，能在最少的人为干预下完成一个多步骤任务（类比成立的前提是任务可拆解、有可调用的工具；纯对话场景不需要 Agent）。

2核心机制

四大组件

  • 规划（Planning）：把用户目标拆成子任务（如"写一篇游记"→ 查景点→查天气→查交通→写大纲→润色）
  • 记忆（Memory）：保留短期上下文（本次会话）和长期事实（用户的偏好、历史结论）
  • 工具（Tools）：调用外部 API、读文件、跑代码——超出语言本身的能力
  • 行动（Action）：执行决定，并把结果反馈给模型以决定下一步

ReAct 循环

思考（Reason）→ 行动（Act）→ 观察（Observe），直到任务完成或需要询问人类。
示例：用户问"北京今天适合跑步吗？"→ Agent 思考需要查天气→ 调用天气工具→ 观察结果 35℃→ 思考"太热，建议室内"→ 输出建议。

3应用场景

  1. 个人助理：自动查日历、订餐厅、整理收件箱（Anthropic Computer Use、ChatGPT Operator）
  2. 研究助手：从 arXiv 下载多篇论文 → 提取方法 → 写综述草稿
  3. 数据分析：读 CSV → 写 SQL → 跑统计 → 出图表，全程只需给目标
  4. 代码助手：在 IDE 里读项目 → 定位 bug → 提 PR（Devin、Claude Code）
  5. 运维告警：收到告警 → 查日志 → 定位服务 → 跑修复脚本

4边界辨析

易混项核心区别
Agent vs LLMLLM 只能"想"，Agent 能"做"——多了工具调用和动作执行
Agent vs ChatbotChatbot 是对话界面，Agent 是执行系统（Agent 可以用 Chatbot 当前端）
Agent vs WorkflowWorkflow 是固定步骤的流水线；Agent 是动态决策的"动态流水线"
常见误解："Agent 能自主完成任何任务"——错。Agent 仍受限于：① LLM 的推理能力上限；② 可用工具的能力边界；③ 任务可拆解的程度。复杂开放任务（如"做一家公司"）它做不了，确定性强的多步骤任务（如下单、查询、写报告）它擅长。
