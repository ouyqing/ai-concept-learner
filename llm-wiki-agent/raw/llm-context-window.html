LLM Context Window（上下文窗口）

Context Window / Token Limit / Context Engineering
领域：大模型 / 工程 读者：入门 深度：基础 检索日期：2026-09-16

1个人解释

把大模型想成一位只有固定长度桌面的图书管理员：你每次把资料摊在桌上，他看一眼就回答，看不完的就漏掉。Context Window 就是这张桌子的最大面积——以 token（一个汉字 ≈ 1-2 token，一个英文单词 ≈ 1-1.3 token）计量。

它是 LLM 的硬约束，决定了"一次对话能塞多少东西"。超出窗口的内容要么被截断、要么被压缩、要么被忘掉（类比成立的前提是承认"窗口"是物理限制而非工程缺陷，注意力机制的复杂度限制了它）。

2核心机制

窗口里装什么

  • 系统提示词（人格、规则、工具说明）
  • 历史对话（user 与 assistant 交替）
  • 当前用户输入
  • RAG 检索片段、工具调用结果

模型当前窗口参考

Claude Sonnet 4：1M token · GPT-4.1：1M token · Gemini 2.5 Pro：1-2M token · 早期 GPT-3.5：16K token

3应用场景

  1. 长文档分析：把整本书塞进窗口做总结（前提：书的 token 数 ≤ 窗口）
  2. 多轮对话：保留较长历史供模型"想起前文"
  3. Agent 任务：工具结果 + 检索片段 + 规划步骤都要塞进窗口——越复杂的 Agent 越需要大窗口
  4. 代码项目：把整个仓库塞进去做跨文件重构

4边界辨析

常见误解 1："窗口越大越好"——部分对。窗口大 ≠ 模型能"有效用"窗口大；超出训练分布的长上下文会迷失在中间（Lost in the Middle），头尾信息记得牢、中间容易丢。
误解 2："窗口无限 = 不用 RAG"——错。窗口是临时内存，RAG 提供经过筛选的相关知识，是不同维度。
